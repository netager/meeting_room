# PRD: 회의 및 회의실 관리

## 목표

사내 회의 채널과 회의실을 통합 관리하여 중복 예약 방지, 참석자 알림 자동화, 감사 추적을 제공하는 사내 전용 폐쇄망 웹 애플리케이션

## 사용자

| 역할 | 설명 |
|------|------|
| **일반 직원** | 회의 채널 생성·조회, 소속 부서 채널 수정, 참석자 메시지 전송 |
| **부서 담당자** | 담당 부서 회의실·집기 등록·수정·관리 (admin이 부여) |
| **시스템 관리자(admin)** | 모든 데이터 CRUD, 권한 부여·해제, 감사 로그 조회, 배치 수동 실행 |

## 운영 환경

- **폐쇄망 Docker** 환경에서 운영 (인터넷 차단)
- 인터넷 환경에서 Docker Image 빌드 → `docker save` → 폐쇄망 전달 → `docker load` → `docker compose up`
- 외부 연동:
  - 사내 메시지 전송 API — 개발 시 Mock, 운영 시 실제 HTTP 연결
  - 인사시스템 ETL — 개발 시 Mock(Admin UI에서 임시원장 직접 편집), 운영 시 ETL 툴이 DB에 직접 INSERT
- 타임존: **Asia/Seoul (KST, UTC+9)** 고정. 서버와 DB 모두 KST 기준

| 필드 | 타입 | 제약 |
|------|------|------|
| 행번 | CHAR(6) | PK, 문자 6자리 |
| 이름 | 문자열 | NOT NULL |
| 소속 부서 | FK | Department, NOT NULL |
| 소속 팀 | FK | Team, nullable |
| 직급 | 문자열 | nullable |

**필드 유효성 규칙:**
- 행번: 정확히 6자리 영문 또는 숫자 조합 (ETL 원본 형식 그대로 유지)
- 이름: 최대 50자
- 직급: 최대 30자

### 2. 직원원장 동기화 (ETL)

#### 임시직원원장(EmployeeStaging)
- ETL 툴이 매일 새벽 외부 인사시스템 데이터를 이 테이블에 **전체 교체(TRUNCATE → INSERT)** 방식으로 적재
- 직원원장과 동일한 필드 구조 (비밀번호 해시, 권한 필드 제외)

#### 새벽 배치 동기화 규칙
| 케이스 | 처리 |
|--------|------|
| 스테이징에만 있음 (신규) | Employee INSERT, 초기 비밀번호 = 행번, EmployeeHistory 기록 |
| 양쪽 모두 있고 내용 다름 (변경) | Employee UPDATE (비밀번호·권한 필드는 덮어쓰지 않음), EmployeeHistory 기록 |
| 양쪽 모두 있고 내용 같음 | 아무 작업 없음 |
| Employee에만 있음 (퇴직) | Employee.status = 퇴직, EmployeeHistory 기록 |

**엣지 케이스:**
- 이미 퇴직 처리된 직원이 스테이징에 재등장하면 → status = 재직으로 복원, 비밀번호는 행번으로 초기화
- 스테이징 TRUNCATE 중 배치가 실행되면 → 배치는 스테이징이 비어 있으면 실행 중단 (전원 퇴직 방지 안전장치)
- 배치 실행 중 예외 발생 시 → 전체 트랜잭션 롤백, AuditLog에 에러 기록, 다음 날 재시도

#### 개발 환경 Mock
- Admin UI(`/admin/employee-staging`)에서 임시원장 데이터를 직접 CRUD
- "동기화 실행" 버튼으로 배치를 수동 즉시 실행 가능

### 3. 인증 및 권한

#### 로그인
- 입력: 행번(6자리) + 비밀번호
- 인증 방식: JWT (Access Token 30분 / Refresh Token 7일)
- Access Token: 클라이언트 메모리 보관
- Refresh Token: HttpOnly 쿠키 (SameSite=Strict)

**최초 로그인 처리:**
- `is_initial_password = true` 인 경우 로그인 성공 후 비밀번호 변경 페이지로 강제 이동
- 비밀번호 변경 전까지 다른 모든 API 요청은 `403 FORCE_PASSWORD_CHANGE` 반환

**비밀번호 정책:**
- 최소 8자 이상
- 영문 + 숫자 조합 필수
- 행번과 동일한 비밀번호 재설정 불가 (초기화 제외)
- 연속 동일 문자 4자 이상 금지 (예: `aaaa`, `1111`)

**로그인 실패 처리:**
- 비밀번호 오류 시 `401 INVALID_CREDENTIALS` (행번 존재 여부를 응답으로 알리지 않음)
- 퇴직 직원 로그인 시도 → `403 ACCOUNT_DISABLED`
- 연속 5회 실패 시 계정 30분 잠금 (`locked_until` 필드 관리)
- 잠금 중 시도 시 `423 ACCOUNT_LOCKED` + 잠금 해제까지 남은 시간 반환

#### Admin 계정
- 계정명 `admin` (직원원장과 분리된 별도 테이블 `admin_account`)
- 초기 비밀번호: `admin123` → 반드시 변경 강제 (is_initial_password 동일 적용)
- 비밀번호 분실 시: 환경 변수 `ADMIN_RESET_TOKEN`으로 `/api/admin/reset-password` API 호출하여 초기화
- admin 계정은 1개만 존재 (추가 생성 불가). 직원에게 admin 권한 부여는 `Employee.is_admin = true`

#### 권한 체계
| 역할 | 권한 |
|------|------|
| `admin` 계정 또는 `is_admin=true` 직원 | 모든 원장 CRUD, 권한 부여/해제, 전체 감사 로그, 배치 실행 |
| `room_manager=true` 직원 | 담당 부서 회의실·집기 CRUD |
| `employee` (기본) | 회의 채널 생성, 소속 부서 채널 수정, 회의실 조회, 회의 자료 다운로드 |

**권한 부여 규칙:**
- admin이 특정 직원에게 `is_admin` 또는 `room_manager` 권한 부여/해제 가능
- 권한 변경 시 해당 직원의 기존 JWT는 즉시 무효화 (블랙리스트 DB 등록)
- 퇴직 직원에게는 권한 부여 불가

#### 회의 채널 수정 권한 상세 규칙
- 수정 가능 대상: 채널 생성자의 **소속 부서 내 모든 재직 직원**
- 팀 단위가 아닌 부서 단위로 적용
- admin 계정과 `is_admin=true` 직원은 모든 채널 수정 가능
- 생성자가 퇴직해도 해당 채널은 부서 내 다른 직원이 계속 수정 가능

### 4. 회의실

#### 회의실(MeetingRoom)
| 필드 | 타입 | 제약 |
|------|------|------|
| ID | UUID | PK |
| 회의실명 | 문자열 | 최대 100자, NOT NULL |
| 위치 | 문자열 | 최대 200자, NOT NULL |
| 상태 | ENUM | `정상` / `임시폐쇄` / `폐쇄` |
| 담당 부서 | FK | Department |

**상태 전이 규칙:**
- `정상` → `임시폐쇄` / `폐쇄`: 언제든 변경 가능
- `임시폐쇄` → `정상` / `폐쇄`: 언제든 변경 가능
- `폐쇄` → `정상` / `임시폐쇄`: admin만 가능

**회의실 폐쇄 시 기존 예약 처리:**
- 상태 변경 시점에 해당 회의실에 `예정` 상태 회의가 있으면 → 변경 허용하되, 담당자에게 경고 메시지 반환 (`200 OK` + `warnings` 배열 포함)
- 기존 예약된 회의는 자동 취소하지 않음 — 담당자가 수동으로 처리
- 담당자 UI에서 해당 회의실의 향후 예약 목록 확인 기능 제공

**회의실 삭제 규칙:**
- 연결된 회의(예정·완료·취소 무관)가 하나라도 있으면 삭제 불가 (`409 CONFLICT`)
- 연결된 집기가 있어도 삭제 불가 → 집기 먼저 삭제 후 회의실 삭제

#### 집기원장(RoomEquipment)
| 필드 | 타입 | 제약 |
|------|------|------|
| ID | UUID | PK |
| 집기명 | 문자열 | 최대 100자 |
| 수량 | 정수 | 1 이상 |
| 비고 | TEXT | nullable |
| 소속 회의실 | FK | MeetingRoom |

- 같은 회의실에 동일 집기명 중복 등록 불가 (`409 CONFLICT`)
- 수량은 1 미만 입력 시 `422 UNPROCESSABLE_ENTITY`

### 5. 회의 채널

#### 회의(Meeting)
| 필드 | 타입 | 제약 |
|------|------|------|
| ID | UUID | PK |
| 회의명 | 문자열 | 최대 200자, NOT NULL |
| 회의 일자 | DATE | NOT NULL |
| 시작 시간 | TIME | NOT NULL |
| 종료 시간 | TIME | NOT NULL |
| 회의실 | FK | MeetingRoom, NOT NULL |
| 회의 내용 | TEXT | nullable, 최대 10,000자 |
| 상태 | ENUM | `예정` / `완료` / `취소` |
| 생성 부서 | FK | Department (자동 설정) |
| 생성자 | FK | Employee (자동 설정) |

**시간 유효성 규칙:**
- 종료 시간 > 시작 시간 필수 (`422 INVALID_TIME_RANGE`)
- 자정을 넘는 회의(예: 23:00~01:00) **불가**. 시작-종료가 같은 날 내에 있어야 함
- 최소 회의 시간: 30분 이상 (`422 MEETING_TOO_SHORT`)
- 최대 회의 시간: 8시간 이하 (`422 MEETING_TOO_LONG`)
- 과거 날짜·시간으로 회의 생성 불가 (`422 PAST_MEETING_TIME`). 단, admin은 과거 날짜도 등록 가능

**회의실 배정 유효성:**
- 선택한 회의실 상태가 `정상`이어야 함 (`409 ROOM_NOT_AVAILABLE`)
- 해당 회의실·날짜·시간 구간에 다른 `예정` 회의가 없어야 함 (`409 ROOM_BOOKING_CONFLICT`)

#### 회의 상태 전이 (State Machine)
```
[예정] ──완료 처리──▶ [완료]
[예정] ──취소 처리──▶ [취소]
[완료] ──▶ 변경 불가
[취소] ──▶ 변경 불가  (취소는 되돌릴 수 없음)
```
- `완료` / `취소` 상태에서는 회의 내용·일시·장소·참석자 수정 불가 (`409 MEETING_ALREADY_CLOSED`)
- 상태를 `예정` → `완료`로 변경하려면 회의 일자가 오늘 이전이어야 함 (미래 회의를 완료 처리 불가)
  - admin은 예외 없이 모두 가능

#### 회의실 중복 예약 방지
- 겹침 조건: `신규.시작 < 기존.종료 AND 신규.종료 > 기존.시작`
- `취소` 상태 회의는 겹침 검사에서 제외
- **동시 요청 경합 처리**: 중복 예약 검사 시 해당 회의실 행에 `SELECT FOR UPDATE` 적용 (비관적 잠금). 먼저 커밋된 요청만 성공하고 나머지는 `409 ROOM_BOOKING_CONFLICT` 반환
- 에러 응답에 충돌하는 기존 회의의 제목·시간 정보 포함 (대안 시간 선택 지원)

#### 참석자(MeetingAttendee)
- 직원원장에서 다중 선택 (재직 직원만 선택 가능)
- 생성자 본인은 자동으로 참석자에 포함
- 최소 1명(생성자 포함), 최대 100명
- 퇴직 직원은 신규 참석자로 추가 불가
- 기존 참석자 중 퇴직한 직원: **자동 제거하지 않음** — 이력 보존 목적. 단, 알림 발송 시 퇴직 직원은 제외

#### 회의 자료(MeetingFile)
| 필드 | 타입 | 제약 |
|------|------|------|
| ID | UUID | PK |
| 원본 파일명 | 문자열 | NOT NULL |
| 저장 파일명 | 문자열 | `{uuid}_{sanitized_name}` |
| 파일 크기 | BIGINT | bytes |
| MIME 타입 | 문자열 | |
| 소속 회의 | FK | Meeting |
| 업로드자 | FK | Employee |

**파일 업로드 규칙:**
- 허용 확장자: PDF, PPT, PPTX, DOC, DOCX, XLS, XLSX, HWP, HWPX, PNG, JPG, JPEG, ZIP
- 단일 파일 최대: 50MB (`413 FILE_TOO_LARGE`)
- 회의당 최대 파일 수: 20개 (`409 FILE_LIMIT_EXCEEDED`)
- 파일명 한글 포함 허용. 저장 시 원본 파일명은 DB에 보존, 디스크 저장명은 UUID prefix 적용
- 허용되지 않은 확장자 업로드 시 `415 UNSUPPORTED_MEDIA_TYPE`
- Content-Type 위조 방지: 확장자와 실제 MIME 타입 모두 검사

**파일 업로드 실패 처리:**
- 업로드 중 서버 오류(디스크 부족, 권한 오류) → DB 기록 없이 `500` 반환, 부분 저장된 파일 즉시 삭제
- 다중 파일 업로드 중 일부 실패 → 전체 롤백 (성공한 파일도 삭제)
- 회의 삭제 시 → 연결된 모든 파일 디스크에서 삭제 후 DB 삭제 (트랜잭션 내에서 파일 삭제는 커밋 이후 수행)

**파일 다운로드 권한:**
- 해당 회의의 참석자 또는 생성 부서 직원만 다운로드 가능
- admin은 모든 파일 다운로드 가능
- 권한 없는 다운로드 요청 → `403 FORBIDDEN`

### 6. 알림 시스템

#### 자동 알림 발송 조건
| 이벤트 | 알림 수신자 | 비고 |
|--------|------------|------|
| 회의 채널 생성 | 생성자 제외 참석자 전원 | |
| 회의명 변경 | 현재 참석자 전원 (재직자만) | |
| 회의 일자·시간 변경 | 현재 참석자 전원 (재직자만) | |
| 회의실 변경 | 현재 참석자 전원 (재직자만) | |
| 회의 내용 변경 | 현재 참석자 전원 (재직자만) | |
| 참석자 추가 | 새로 추가된 참석자만 | |
| 참석자 제거 | 제거된 참석자만 | "참석자에서 제외되었습니다" |
| 상태 → `취소` | 현재 참석자 전원 (재직자만) | |
| 상태 `예정` → `완료` | 알림 없음 | |

**알림 발송 제외 케이스:**
- 퇴직 직원은 알림 대상에서 제외 (발송 시도 자체를 하지 않음)
- 발송자 본인에게는 알림하지 않음

**알림 발송 실패 처리:**
- HTTP 전송 실패(타임아웃, 5xx) 시 **최대 3회 재시도** (1분 간격)
- 3회 모두 실패 시 → `MessageLog.status = FAILED` 기록 후 더 이상 재시도하지 않음
- 알림 발송 실패가 회의 채널 저장 자체를 실패시키지 않음 (비동기 처리)
- 실패 건은 Admin UI에서 조회 및 수동 재발송 가능

#### 참석자 직접 메시지 전송
- 발신자: 해당 회의 참석자이거나 생성 부서 직원
- 수신자: 전체 또는 개별 선택 (퇴직 직원 선택 불가)
- 메시지 내용: 최대 1,000자
- 빈 메시지 전송 불가 (`422 EMPTY_MESSAGE`)

#### 사내 메시지 전송 API 명세 (Mock)
```
POST {INTERNAL_MSG_API_URL}
Content-Type: application/json

{
  "sender": "행번 또는 system",
  "recipients": ["행번1", "행번2"],
  "message": "메시지 내용",
  "ref_type": "MEETING",
  "ref_id": "회의 UUID"
}
```
- 실제 API 연결 시 payload 구조가 다르면 `notification_service.py` 내 변환 레이어 추가
- 타임아웃: 5초 (`INTERNAL_MSG_API_TIMEOUT` 환경 변수로 조정 가능)

### 9. 비기능 요구사항

#### 성능
- 목록 API 응답: 95th percentile 500ms 이하
- 파일 업로드: 50MB 파일 기준 60초 이내
- 동시 사용자: 50명 이상 지원

#### 보안
- 비밀번호: bcrypt(cost=12) 해싱
- SQL Injection: SQLAlchemy ORM 파라미터 바인딩으로 방지 (raw query 금지)
- XSS: Svelte의 기본 이스케이프 + Content-Security-Policy 헤더 설정
- CSRF: SameSite=Strict 쿠키 + custom header 확인
- 파일 업로드: 저장 경로 외부 노출 금지, 저장명은 UUID 기반
- JWT secret 키: 최소 256bit(32바이트) 랜덤 값

#### 가용성
- 단일 서버 운영 (폐쇄망 제약). HA 구성 불필요
- 계획된 다운타임: 배포·마이그레이션 시 허용
- DB 백업: 매일 새벽 pg_dump (docker-compose cron 또는 별도 스크립트)

#### 참석자 선택기 (AttendeeSelector) 상세 동작

1. 검색창에 이름 또는 행번 입력 → 300ms 디바운스 후 API 호출
2. 드롭다운에 최대 10명 표시 (더 있으면 "더 구체적으로 검색하세요" 안내)
3. 항목 클릭 → 선택된 참석자 칩(chip) 추가
4. 이미 선택된 직원은 드롭다운에서 비활성화 표시
5. 본인(생성자)은 기본 포함되어 삭제 불가 (칩에 자물쇠 아이콘)
6. 검색 결과 없음 → "검색 결과 없음"
7. 칩의 ✕ 클릭 → 참석자 제거 (본인 제외)

#### 피드백 패턴 (Toast / Modal)

**Toast 알림:**
- 위치: 화면 우측 하단 고정
- 성공: 초록색, 3초 후 자동 사라짐
- 에러: 빨간색, 5초 후 자동 사라짐 + 수동 닫기 버튼
- 경고(회의실 폐쇄 시 기존 예약 존재): 노란색, 수동 닫기 필수
- 동시에 최대 3개까지 쌓임 (그 이상은 가장 오래된 것부터 제거)

**확인 모달 (파괴적 행위 전):**

| 행위 | 제목 | 내용 | 버튼 |
|------|------|------|------|
| 회의 삭제 | "회의를 삭제하시겠습니까?" | "삭제된 회의와 첨부 파일은 복구할 수 없습니다." | [취소] [삭제] |
| 회의 취소 처리 | "회의를 취소하시겠습니까?" | "취소된 회의는 되돌릴 수 없으며, 참석자에게 취소 알림이 발송됩니다." | [닫기] [취소 처리] |
| 파일 삭제 | "파일을 삭제하시겠습니까?" | "{파일명}을 삭제합니다. 복구할 수 없습니다." | [취소] [삭제] |
| 회의실 폐쇄 처리 | "회의실을 폐쇄하시겠습니까?" | "{N}건의 예정된 회의가 있습니다. 해당 회의는 취소되지 않으므로 직접 처리하세요." | [취소] [폐쇄 처리] |

- 위험 버튼(삭제, 취소 처리)은 Danger 스타일
- 기본 포커스는 항상 안전한 버튼 (취소/닫기)

#### 빈 상태 (Empty State)

| 페이지 | 빈 상태 텍스트 | 액션 |
|--------|--------------|------|
| 내 회의 (오늘) | "오늘 예정된 회의가 없습니다." | [회의 만들기] 버튼 |
| 내 회의 (전체) | "참석 중인 회의가 없습니다." | [회의 만들기] 버튼 |
| 전체 회의 (검색 결과 없음) | "검색 조건에 맞는 회의가 없습니다." | 필터 초기화 링크 |
| 회의실 목록 | "등록된 회의실이 없습니다." | (room_manager에게만) [회의실 등록] 버튼 |
| 파일 목록 | "첨부된 파일이 없습니다." | |
| 감사 로그 | "조회 조건에 해당하는 기록이 없습니다." | |

- 빈 상태는 `text-center` 정렬 (이 경우만 허용)
- 아이콘 없이 텍스트만 (AI 슬롭 방지)

#### 로딩 상태

- **목록 페이지**: 테이블 행 스켈레톤 (3~5행의 회색 블록)
- **상세 페이지**: 필드별 스켈레톤 (실제 레이아웃과 동일한 구조)
- **버튼 클릭 후 처리 중**: 버튼 비활성화 + 텍스트 "처리 중..." (스피너 없음)
- **파일 업로드**: 진행률 표시줄 + "N% 업로드 중..." 텍스트
- **참석자 검색**: 드롭다운에 "검색 중..." 텍스트 (스피너 없음)

스켈레톤 스타일:
```
rounded bg-neutral-800 animate-pulse
```

#### 파일 업로드 UX

- **드래그 앤 드롭** + **클릭하여 선택** 모두 지원
- 드래그 오버 시 점선 테두리 강조
- 다중 파일 선택 가능 (OS 파일 선택창에서 Ctrl+클릭)
- 업로드 진행 표시:
  ```
  보고서_최종.pdf  ████████████░░░░░░░░  60%  [취소]
  발표자료.pptx    ░░░░░░░░░░░░░░░░░░░░   대기 중
  ```
- 허용되지 않은 파일 선택 시 → 파일 목록에 빨간색으로 표시 + "지원하지 않는 형식"
- 50MB 초과 시 → 선택 즉시 클라이언트에서 차단 (서버 요청 전)

#### 세션 만료 UX

- **AT 만료 중 요청**: fetch 래퍼가 자동으로 RT로 AT 갱신 → 원래 요청 재시도 (사용자 인지 불가)
- **RT도 만료**: 로그인 페이지로 이동 + "로그인 세션이 만료되었습니다. 다시 로그인해 주세요." 토스트
- **작업 중 세션 만료**: 현재 입력 중인 폼 데이터는 손실됨 (sessionStorage 보존 미적용, MVP 제외)

#### 페이지 이탈 경고 (Unsaved Changes)

- 회의 생성/수정 폼에서 내용 입력 후 **다른 페이지로 이동** 시 브라우저 확인창 표시
  - "변경 사항이 저장되지 않습니다. 이동하시겠습니까?"
- 적용 대상: 회의명, 내용, 참석자, 일시, 회의실 중 하나라도 변경된 경우
- 제출 성공 또는 명시적 [취소] 클릭 시 → 경고 없이 이동

#### 최초 로그인 비밀번호 변경 페이지

```
┌─ 비밀번호 변경 필요 ─────────────────────────────────────┐
│                                                           │
│  처음 로그인하셨습니다.                                   │
│  보안을 위해 비밀번호를 변경해 주세요.                    │
│                                                           │
│  현재 비밀번호 (행번)                                     │
│  [••••••]                                                 │
│                                                           │
│  새 비밀번호                                              │
│  [              ]                                         │
│  ✗ 8자 이상   ✗ 영문 포함   ✗ 숫자 포함                 │  ← 실시간 정책 충족 여부
│                                                           │
│  새 비밀번호 확인                                         │
│  [              ]                                         │
│                                                           │
│                          [변경 완료]                      │
└───────────────────────────────────────────────────────────┘
```

- 비밀번호 정책 충족 조건을 실시간으로 ✓/✗ 표시
- 변경 완료 후 → 내 회의 페이지로 이동 + "비밀번호가 변경되었습니다." 토스트

#### 계정 잠금 UI

## MVP 제외 사항

- 반복 예약 (매주·매월 정기 회의 자동 생성)
- 외부 캘린더 연동 (Google Calendar, Outlook 등)
- 회의실 좌석 수 / 평면도 관리
- 모바일 앱 / 반응형 최적화 (데스크톱 우선, 최소 1280px)
- 다국어(영문) 지원
- 이메일 알림 (사내 메시지 전송만 사용)
- 회의록 자동 생성 / AI 요약
- 파일 미리보기 (다운로드만 제공)
- 회의실 층별 배치도
- SSO / LDAP 연동
